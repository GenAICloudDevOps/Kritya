# Kritya v0.2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rename code-cli → **kritya** and ship 9 Tier-1 features: context auto-compaction, mid-run steering, richer shell (timeouts/background/tail-truncation), permission allowlists, git awareness + turn checkpoints, syntax highlighting, session titles/search, `/init` + prompt-injection hygiene, and Windows CI.

**Architecture:** Existing lean layering stays: `provider/` (OpenAI-compatible streaming client) → `agent/` (tool loop) → `tools/` (ToolDef registry) → `ui/` (Ink React). New modules: `src/shell/background.ts` (background process registry), `src/git/git.ts` (branch/status helpers), `src/agent/compactor.ts` (history summarization), `src/ui/highlight.ts` (regex syntax highlighter). Permission allowlists extend `PermissionManager` with settings-file rules. No new runtime dependencies.

**Tech Stack:** TypeScript 5, Node 18+, Ink 5, `openai` SDK against build.nvidia.com, `node --test` for tests, GitHub Actions CI.

## Global Constraints

- Product name everywhere: **kritya**; binary `kritya`; config dir `~/.kritya`; project memory file `KRITYA.md` (fallback: `CODECLI.md`); project settings `<workspace>/.kritya/settings.json`.
- Env var stays `NVIDIA_API_KEY`; base URL unchanged.
- No new runtime npm dependencies (dev deps for CI/testing OK).
- All file tools remain confined to the workspace (`resolveSafe`).
- Tests run via `npm test` (`tsc` build then `node --test dist/test/**/*.test.js`).
- Node >= 18, must pass on Linux, macOS, Windows.

**Interfaces:**

- `compactor.ts` exports `splitForCompaction(history): { toSummarize: ChatMessage[]; keep: ChatMessage[] }` — keeps the last ≥8 messages but never cuts between an assistant tool_calls message and its tool replies (boundary must be a `user` message or an assistant message without `tool_calls`), and `renderTranscript(msgs): string`.

**Behavior:**
- `compact()` calls the model (no tools) with: system "Summarize this coding-session transcript into a dense briefing: goals, decisions, files touched, current state, open items." + transcript; replaces `history` with `[{role:"user", content:"[Conversation summary of earlier work]\n" + summary}, ...keep]`; rotates session file and re-persists.
- In `runTurn`, after each `onUsage`, if `lastPromptTokens > 0.8 * contextWindow` and history length > 12, run compaction between iterations and notify via `handlers.onToolEnd("compact", "Auto-compacted context", ...)`.
- App: `/compact` command; statusline gains `ctx {pct}%` (from `agent.contextUsage()`, refreshed via onUsage handler).

**Steps:**
- [ ] Test `splitForCompaction` never splits tool-call pairs and keeps ≥8 tail messages (construct history with assistant+tool_calls followed by tool msgs at the cut point).
- [ ] Run test → fails; implement `compactor.ts`; test passes.

**Steps:**
